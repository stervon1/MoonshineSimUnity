# White Lightning — Moonshine Distilling Simulator

Self-directed, tactile distilling process sim in Unity 6 (URP). You run a
small off-the-books still, sell jars quietly out the back of restaurants for
cash, and grind toward a license + legal facility. Reference points: Car
Mechanic Simulator, PowerWash Simulator — low-stakes craft-mastery loop; the
early illegality is texture (cash out the back door), **never danger** — no
busts, no heat meter, no crime-drama. (v3 spine — replaced client-given jobs;
see `docs/design-doc.md`.)

## Read first
- `docs/design-doc.md` — full design spec (systems, workshop tiers, tone)
- `docs/project-plan.md` — milestones + live "current state"; **we're on Milestone 1**
- `docs/distillation-reference.md` — reconciled process facts + a synthesised
  still-run simulation model (§9) for tuning `StillRunController`

## Architecture
- `Assets/Scripts/Core/` — plain C#, no Unity deps where possible: `GameState`
  (singleton: `CurrentBatch`, `Cash`, `Rapport`; `OnBatchStarted` /
  `OnBatchStageChanged` / `OnBatchSold`), `BatchPlan` + `BatchPlanGenerator`,
  `BatchState`/`BatchStage`, `Buyer` + `BuyerGenerator`, `BatchAppraisal`,
  `ProofingUtility`.
- `Assets/Scripts/Gameplay/` — `StillRunController` (centerpiece), `BatchController`
  (batch state machine + buyer roster, bridges GameState), `FirstPersonController`,
  interaction (`IInteractable` / `PlayerInteractor` / `Interactable` / `Carryable`),
  world stations (`GrainBin`, `MashStation`, `FermentStation`, `ProofingStation`,
  `BuyerCounter`), feel (`ProofGauge`, `StillFX`, `StillAudio`).
- `Assets/Scripts/UI/` — **the clipboard is the only screen UI**: `ClipboardModel`
  (Unity-free) + `ClipboardController`. Everything else is a world interaction.
- `Assets/Editor/` — `Tools > White Lightning > Rebuild Prototype` runs the whole
  pipeline; individual builders under `…/Steps/`. `BuildScript` = headless build.
- Scenes/props are **generated by the editor tool scripts**, not hand-written
  YAML. `Assets/Scenes/Prototype.unity` is the committed playable scene; run
  `Rebuild Prototype` after script changes that touch scene wiring.

## Conventions
- Namespace by folder: `MoonshineSim.Core`, `MoonshineSim.Gameplay`, `MoonshineSim.UI`
- Simulation logic stays plain C#, decoupled from MonoBehaviour/UI where possible
  (see `ProofingUtility` as the pattern — static, no Unity dependencies)
- No hard-fail states in gameplay systems — mistakes lower a quality score,
  never block progress (this is a design constraint, not just a code style note)

## Cross-machine continuity (git + Git LFS)
This repo syncs between machines (Windows ⇄ Mac) via git — remote
`github.com/stervon1/MoonshineSimUnity`, branch `main`. Binary assets (fbx, png,
wav, …) are stored in **Git LFS** per `.gitattributes`; run `git lfs install`
once per machine. Claude Code's `~/.claude/` memory does **not** sync, so resume
state lives in `docs/claude/` and rides along in commits. See
`docs/claude/README.md`.

- **At session start:** read `docs/claude/SESSION.md` (the handoff) and
  `docs/claude/project-map.md` (generated structural snapshot). If your local
  memory index (`MEMORY.md`) is empty or thinner than `docs/claude/memory/MEMORY.md`,
  import the missing files into local memory first.
- **If the map looks stale** — its `<!-- newest-source: … -->` line is behind the
  newest file under `Assets/Scripts` or `Assets/Editor`, or you just added/renamed/
  deleted a script — regenerate it: `pwsh Tools/regen-claude-map.ps1` (Windows) or
  `bash Tools/regen-claude-map.sh` (Mac), or *Tools > White Lightning > Regenerate
  Claude Map* in the editor.
- **Before handing back** (or on "checkpoint" / "handoff" / "wrap up"): update
  `docs/claude/SESSION.md` — bump the `Last updated` / `Machine` header, rewrite
  *In progress* and *Next steps*, prepend one *Rolling log* bullet. Regenerate the
  map if structure changed. Mirror any new/changed local memory files into
  `docs/claude/memory/`. Then commit `docs/claude/` (and any real work) and
  `git push` so the next machine gets it; on the other machine start with
  `git pull`.

## Commands
- Open project: Unity Hub → Add → this folder. Editor version is whatever
  `ProjectSettings/ProjectVersion.txt` says — currently **6000.5.10f1** (Hub will
  offer to install it). That file is the source of truth; this line may lag it.
- Play: open `Assets/Scenes/Prototype.unity` → Play. Rebuild via `Tools > White
  Lightning` (order in `README.md`).
- CLI batch build: `Unity -batchmode -nographics -projectPath . -executeMethod BuildScript.Build -quit`
  (`Assets/Editor/BuildScript.cs` — compile-gates headlessly; real player build
  once a scene is in Build Settings)
