Scenes/props for this project are generated by editor scripts under
`Assets/Editor/` (menu: **Tools > White Lightning**), not hand-authored — keeps
them reproducible and dodges CLAUDE.md's "no hand-written YAML" rule.

Run order matters (each builds on the prior scene state):
1. `Set Up URP Pipeline` — one-time; project shipped without a URP asset assigned.
2. `Build Prototype Scene` — GameState + Still + Canvas + prototype UI → `Assets/Scenes/Prototype.unity`.
3. `Build Basement Room` **or** `Build Outdoor Sandbox` — swappable environment
   root into the active scene (each removes the other's root).
4. `Add First-Person Player` — CharacterController rig, reuses Main Camera as the eye.
5. `Add Still Interaction Rig` — white-block `Interactable`s + HUD + authors the
   `proofCurve` AnimationCurve on `StillRunController`.
6. `Add Clipboard` — toggleable (Tab) job checklist + live-data HUD
   (`ClipboardModel` is Unity-free; `ClipboardController` maps events onto it).

`BuildScript.Build` is the headless CI entry (compile gate until a scene is in
Build Settings). Can't drive the Unity Editor GUI directly — hand the user the
menu path and have them run it. Only one Unity batch process at a time or it
aborts on the project lock. See [[keep-project-plan-updated]].
